# speedtester

Консольный замер скорости интернета: делает последовательные запросы
к одному адресу, считает среднее время запроса, общий объём скачанного
и скорость скачивания.

## Запуск (uv)

```bash
uv sync                 # установить зависимости (httpx, pytest)
uv run main.py https://example.com/big.jpg
```

Опции:

```bash
uv run main.py <url> [-n N] [--timeout SEC]
```

- `<url>` - адрес, к которому стучимся (нужен `http://` или `https://`);
- `-n, --requests N` - количество последовательных запросов, по умолчанию `10`;
- `--timeout SEC` - таймаут одного запроса, по умолчанию `30`.

Пример:

```bash
uv run main.py https://speed.cloudflare.com/__down?bytes=25000000 -n 10
```

Тесты:

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

## Единицы измерения

| Показатель | Формула | Единица |
|---|---|---|
| Объём | сумма байт успешных ответов | MB = 10⁶ байт |
| Среднее время | суммарное время / число успешных запросов | ms |
| Скорость | суммарный объём / суммарное время | Мбит/с = 10⁶ бит/с и МБ/с = 10⁶ байт/с |

Все единицы десятичные (SI), поэтому Мбит/с и МБ/с различаются ровно
в 8 раз, как в популярных онлайн-тестах скорости.

Неудачные запросы в статистику не входят: объём и время считаются
только по успешным ответам, число ошибок показывается отдельной строкой.

## Архитектура

Модули лежат плоско, зависимости идут в одну сторону:

```
main.py             точка входа: аргументы, сборка, коды возврата
src/http_client.py  транспорт: запрос к адресу через httpx
src/report.py       предметная область: адрес, итог запроса, отчёт
src/speedtest.py    сценарий: N последовательных запросов
src/formatting.py   представление: отчёт для консоли
```

Слои:

- **предметная область** (`report`) ничего не импортирует из проекта;
- **транспорт** (`http_client`) знает только про сущности;
- **сценарий** (`speedtest`) собирает транспорт и сущности в отчёт;
- **представление** (`formatting`) рисует отчёт, не считая ничего;
- **сборка** (`main`) держит всё вместе и не содержит логики.

Две абстракции намеренно не заводились:

- порт `HttpClient` (ABC) при единственной реализации на httpx -
  второго транспорта задача не просит, это YAGNI;
- класс-обёртка `Application` вокруг одного вызова `run()` -
  контекстный менеджер остался там, где есть ресурс (`HttpxClient`),
  а не там, где есть только оркестрация.

Повторов нет: ровно `N` запросов, как в задании. Неудачный запрос
не прерывает прогон - он попадает в отчёт с текстом ошибки, и замер
продолжается; статистика считается по успешным запросам.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | замер выполнен |
| 1 | неверный адрес или не удался ни один запрос |
| 2 | неверные аргументы командной строки |
